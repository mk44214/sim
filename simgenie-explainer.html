The Core Concept

One engine. Every domain.

The architectural insight: a hospital simulation and a supply chain stress-test share the same mathematical skeleton. Only the domain model changes — the engine never does.

🔀

Inject a change

Modify any parameter — a policy, a resource level, a price — and the engine forks reality at that point in time.

⚡

Run forward in time

The discrete-event engine jumps tick-by-tick through causal consequences, running hundreds of parallel futures simultaneously.

📊

Get probability-weighted outcomes

Not a single prediction — a distribution. "There's a 73% chance ICU occupancy exceeds 95% within 14 days."

🔄

Swap the domain

Change one YAML schema file and the same engine models insurance loss ratios, portfolio drawdowns, or pharma clinical trial yield.

Architecture

Five layers — one invariant core

Click any layer to expand. Layers 2–5 are universal across every vertical. Only Layer 1 changes.

L1
Domain Model
YAML schema — entities, events, relationships, time scale
One .yaml file per vertical. Declares entity types, event types, relationship semantics, and simulation time unit (milliseconds to months). Swapping this file transforms the entire simulation. 39 schemas exist — hospitals, supply chains, insurance, aviation, pharma, maritime, energy grids, and more. No Python changes required.
🔁 Swappable
L2
Simulation Core
State machine + time-step engine · Agent-based · System dynamics · Discrete event · Monte Carlo
Immutable WorldState snapshots. Variable time-step DES — the clock jumps to the next scheduled event, skipping empty time. Events are the only mechanism for state change. Core components: Entity, RelationshipGraph, EventQueue, SimulationRunner, ParallelSimulationRunner.
🔒 Universal
L3
Uncertainty & Calibration
Bayesian inference · Distribution fitting · Sensitivity analysis · ABC calibration
Every parameter is a distribution, not a point estimate. Inputs are sampled at runtime. Approximate Bayesian Computation (ABC) tunes the model against observed real-world data. Confidence intervals on every output metric. This is the "trust layer" — the engine quantifies exactly what it doesn't know.
🔒 Universal
L4
Scenario Management
Branching · Parameter sweep · Comparison · Audit trail
ScenarioManager forks WorldState snapshots with full lineage — version control for reality. ParameterSweep fans out over a parameter grid automatically. Every attribute delta is recorded in an immutable audit trail. Compare any two branches side-by-side.
🔒 Universal
L5
Output & Reasoning
LLM-generated narratives · Probability distributions · Confidence intervals · Goal-seek
The Anthropic Claude API generates plain-language narratives using the tool_use pattern — the model reads real numbers from structured simulation output, it never guesses. 4 narrative types: executive summary, risk analysis, sensitivity report, goal-seek explanation. SQLite WAL backend for run persistence; JSON fallback.
🔒 Universal

Immutability is the superpower

Every WorldState is frozen=True. Events don't mutate — they produce a new snapshot. This makes branching trivial (fork any snapshot at any tick), parallelism safe (Ray workers never share mutable state), and audit trails exact (every historical state is addressable).

frozen=True fork-safe Ray-parallel seed-reproducible
# Entity is frozen — all mutations return new instances
patient = Entity("p-01", "Patient")
admitted = patient.with_attribute(
"icu_admitted", True
)

# Old state still intact — branching is free
assert patient.get("icu_admitted") is None

Parallel Uncertainty

Every run is one possible future

Monte Carlo fan-out via Ray: hundreds of independent simulation runs, each with a different random seed and sampled parameters. The output is a probability distribution, not a single number.

Independent reproducibility

seed = base_seed + run_id — every run is independently replayable. Ray distributes work across CPU cores with no shared mutable state between workers. Thread-pool fallback when Ray isn't needed.

Confidence intervals on everything

Avg wait time (hrs)1.2 – 4.7

Output & Reasoning

Numbers become decisions

The LLM narrative engine reads structured simulation output and generates plain-language analysis. No hallucinated numbers — the model uses the tool_use pattern to read real metrics directly from the run.

"Based on the simulation, if ICU capacity remains at current staffing levels, there is a 78% probability that occupancy will exceed the 90% critical threshold within 11 days, peaking at an estimated 97% (CI: 89%–100%). The primary driver is not patient volume — which is within seasonal norms — but the nursing vacancy rate of 18%. The model identifies two leverage points with asymmetric impact: adding 3 float nurses reduces peak occupancy by 14 percentage points; extending discharge processing by 2 hours has no statistically significant effect."
